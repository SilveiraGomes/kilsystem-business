## 6. Limitação de tentativas

Código compilado, relógio injectado, base real:

| Verificação | Resultado |
| --- | --- |
| 3 falhas livres | 3 × `invalid-recovery-code`; a 4.ª `throttled` com 60 s |
| Progressão | 120, 240, 480, 960, 1920, 3600, 3600, 3600 s — limitada a 3600 s |
| Código **correcto** durante o bloqueio | `throttled`, sem verificação; o código continua `ACTIVE` (não há caminho que verifique o código sem contar) |
| Reinício do processo | novo serviço sobre a mesma base: continua bloqueado (> 3000 s) e o contador não reinicia |
| Relógio recuado 2 h | uma tentativa admitida (o bloqueio "no futuro" não se aplica — comportamento de D-094) e a seguinte volta a bloquear 3600 s; o contador não diminui |
| Relógio avançado | depois de 3600 s, admitida: nunca permanente; ≥ 7 dias sem tentativas esquecem o contador (DP-06) |
| Concorrência | R-S02b (8 tentativas simultâneas: 3 admitidas, 5 recusadas), executado; RM-03 detectada |
| Recusas por limitação | agregadas em `refused_count`, sem eventos (R-S11) |
| Diferenças de resposta | perante o segredo só `invalid-recovery-code` ou sucesso; `malformed`, `password-rejected` e `throttled` são imediatos e não dependem do código (§7 da especificação) |
| Tempo | sem código activo (`burn`) ≈ 219–229 ms; código errado com código activo ≈ 263–264 ms (amostras em processo frio/quente; mesma ordem de grandeza, mesmo custo Argon2id) — sem oráculo útil num código de 160 bits |

A verificação do código só existe em `recover` (`verifyCode`), sempre depois da admissão contada; `rotate` não lê nem verifica o código. O ataque *offline* ao verificador (D-209) é um Argon2id de 64 MiB sobre 160 bits: inviável.

Com controlo do relógio do sistema, cada recuo de mais de 60 s dá uma tentativa extra e um avanço de 7 dias esquece o contador; isto é herdado de D-094/DP-06 e irrelevante para 160 bits (Informativo, sem achado novo).
