# E1.05 — Proposta: composição do serviço local de dados

- Estado: **proposta, não autorizada**. Não implementar sem autorização explícita do responsável do projecto.
- Origem: redigida no fecho de E1.04 a partir do estado do repositório; não consta de planeamento anterior. O responsável pode aprovar, ajustar ou substituir este âmbito.
- Commit esperado: a definir na autorização.

## Justificação

`packages/database` existe como biblioteca, mas nenhum serviço a utiliza. Segundo D-028, a base pertence à camada de serviços locais (`services/local-api`). Antes de expor dados é preciso definir como esse serviço arranca, encontra a base, aplica migrações e encerra com segurança.

## Âmbito proposto

1. Leitura e validação da configuração local (`LOCAL_DATABASE_PATH` via `resolveDatabaseLocation`, `LOCAL_API_HOST`, `LOCAL_API_PORT`), com falha explícita quando ausente.
2. Arranque de `services/local-api`: abrir a base, aplicar migrações e criar a persistência. Falha controlada perante base incompatível (`unknown-schema-version`, `migration-checksum-mismatch`).
3. Encerramento ordenado: fechar o servidor e depois a ligação SQLite.
4. Testes de arranque e encerramento com bases temporárias.

## Fora de âmbito proposto

Endpoints com dados empresariais (exigem autenticação), autenticação, comunicação Electron/API, sincronização, PostgreSQL, alterações visuais e regras fiscais, contabilísticas ou sectoriais.

## Decisões a obter antes de iniciar

- Processo e runtime dos serviços locais (Node autónomo ou processo gerido pelo Electron). Um runtime Electron exige recompilar o `better-sqlite3` para a ABI do Electron (PD-10).
- Se o arranque inclui um endpoint técnico de estado, sem dados empresariais, ou nenhum endpoint.
- Ordem relativa face à autenticação. A alternativa é antecipar uma etapa de autenticação local, porque o `TenantContext` tem de vir de identidade autenticada (`AGENTS.md`).

## Critérios de aceitação propostos

- `pnpm check` aprovado e smoke test Electron inalterado.
- Suite de contrato multiempresa continua aprovada.
- Documentação e decisões actualizadas; commit único em Conventional Commits.
